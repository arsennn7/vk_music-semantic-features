# Семантические признаки музыкальных треков для рекомендаций по интенту

Тестовое задание к проекту ИМШ НИУ ВШЭ × VK «Генерация плейлистов по запросу пользователя».

**Ноутбук:** [`VK_TASK2740.ipynb`](VK_TASK2740.ipynb) · [![Open In Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/arsennn7/vk_music-semantic-features/blob/main/VK_TASK2740.ipynb)


Пользователь формулирует запрос через ощущения и ситуацию («что-нибудь спокойное, чтобы уснуть»),
а у трека есть только метаданные каталога. Цель работы — обогатить треки семантическими признаками
(жанр, настроение, контекст, атмосфера, энергия, вокал, эпоха), извлечь их автоматически
и проверить, какие из них действительно отражают похожесть музыки.

## Что сделано

| Задание | Содержание |
|---|---|
| 1. Датасет | 80 треков, 8 жанров по 10, ≤ 2 трека на артиста; Deezer API: 30-секундные превью, метаданные, похожие артисты; автоматический отбор правильной записи + две проверки качества |
| 2. Признаки | закрытый словарь настроений, контекстов и атмосфер; энергия и валентность (модель Рассела); вокал, эпоха, жанр, язык |
| 3. Извлечение | `librosa` (темп, громкость, ритмичность, яркость), CLAP `laion/larger_clap_general` (аудио-эмбеддинги + zero-shot теги), `Qwen2.5-7B-Instruct` в 4 bit (жанр, эпоха, теги, описание) |
| 4. EDA | распределения тегов по источникам, профиль настроений по жанрам, карта энергия × валентность, корреляции, согласие CLAP и LLM |
| 5. Похожесть | 6 представлений треков, kNN по косинусу, метрики на двух эталонах, UMAP, примеры соседей, поиск треков по тексту через CLAP |

## Главные результаты

| Представление | Жанр P@5 | Похожий артист в топ-10 |
|---|---|---|
| случайные векторы | 0,11 | 0,17 |
| librosa | 0,26 | 0,42 |
| LLM теги | 0,42 | 0,65 |
| CLAP теги | 0,48 | 0,63 |
| CLAP аудио | 0,57 | 0,79 |
| LLM текст | 0,66 | 0,75 |
| **CLAP аудио + LLM текст** | **0,71** | **0,86** |

- Звук (CLAP) и знания (LLM) дополняют друг друга: комбинация лучше по обоим эталонам.
- Эмбеддинги лучше тегов для похожести; теги нужны для фильтров и объяснимости.
- Надёжные признаки: вокал (точность CLAP 0,79, LLM 0,90), жанр от LLM (0,90), энергия.
  Ненадёжные: валентность, атмосфера, темп.
- LLM хуже знает русскоязычную музыку и почти всегда уверена в ответе.
- `laion/larger_clap_music` даёт вырожденные эмбеддинги (zero-shot жанр на уровне случайного),
  поэтому выбран `larger_clap_general`.

## Как запустить

1. Открыть ноутбук в Colab по ссылке выше.
2. **Среда выполнения → Сменить среду выполнения → T4 GPU.**
3. **Среда выполнения → Выполнить все.**

Ноутбук сам скачивает `seeds.csv` и собранный датасет из этого репозитория, а аудио-превью — с Deezer.
Ответы LLM закэшированы в `data/llm_raw.json`, поэтому Qwen при запуске не загружается.

Первая ячейка ставит `transformers<5`: с transformers 5.x модели в ноутбуке не проверялись.

## Структура

```
├── VK_TASK2740.ipynb        ноутбук со всеми заданиями и выводами (сохранён с результатами)
├── seeds.csv                исходный список треков: основные + резерв
├── data/
│   ├── tracks_meta.jsonl    собранный датасет (метаданные Deezer)
│   └── llm_raw.json         ответы LLM, привязанные к id треков
└── figures/                 графики из EDA и задания 5
```

Аудио в репозиторий не входит: превью защищены авторским правом, ноутбук скачивает их заново.

## Ограничения

- 80 треков, отобранных вручную; жанровые ярлыки местами спорны.
- Каталог Deezer зависит от региона сервера, поэтому датасет зафиксирован в `data/tracks_meta.jsonl`.
- Эталоны похожести косвенные: жанр и «похожие артисты» Deezer.
- Часть решений (центрирование тегов CLAP, выбор чекпоинта) принята на тех же данных, на которых оценивалась.
